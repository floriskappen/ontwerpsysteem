# Decisions — effects-as-pure-data-modules

Places where the tasks were weaker than, or diverged from, the specs they implement,
and implementation calls the artifacts did not anticipate. Each: what was done, what
was rejected, why.

## 1. `weatherTextData` carries spaces; the wrapper renders one node per datum

- **Tension.** Task 1.3 pins the shape only as `weatherTextData(str) → {char,index}[]`.
  The spec (effects-contract / Wrapper renders from the data function) demands the data
  function be "the single source of the field's cardinality" and that the wrapper render
  exactly one element per datum. The legacy output renders word spaces as bare text
  nodes between spans — no element — and byte-parity with the accepted baseline forbids
  wrapping them in elements. So "data excludes spaces" breaks single-source-of-cardinality;
  "data includes spaces" breaks one-*element*-per-datum read literally.
- **Done.** The data carries every character of the phrase, spaces included, each with its
  position in the source string (spaces consume an index too, so `--ci` stays aligned).
  The wrapper emits exactly one *node* per datum: a span for glyphs, a literal space where
  the phrase breathes. The contract test asserts 1:1 nodes-in-order for weatherText and
  reserves the strict one-element-per-datum assertion for the field generators.
- **Rejected.** Excluding spaces from the data (the wrapper would re-introduce layout the
  data no longer describes); emitting space elements (changes shipped bytes).

## 2. Weather particle datums are `{ cls, index, vars }` with render-ordered vars

- **Gap.** The artifacts name the type (`Particle[]`) but not the shape.
- **Done.** Each particle is `{ cls: string, index: number, vars: Record<string,string> }`
  where `vars` holds the CSS custom properties in exact render order. This makes one
  three-line renderer serve all eight fields, keeps attribute order part of the data (so
  byte-parity is structural, not luck), and handles wind's two sub-shapes (gusts + motes)
  without per-kind branching in the wrapper. Coordinates and animation parameters are all
  there — as the values the shipped effects CSS actually animates by.
- **Rejected.** Flat named numeric fields per kind (`{y, len, d, …}`): needs eight parallel
  field→attribute tables in the wrappers to preserve bytes — presentation logic duplicated
  next to the data it must not diverge from — and still forces a class/discriminator into
  the datum for mixed fields like wind.

## 3. Grid cell values stay unitless strings; units applied at render

Task 1.2's `{a,b,d,dl,index}` is implemented literally: the formatted strings from the
original computation, units appended by the wrapper (`--d:${d}s`). Rejected storing
unit-suffixed strings in the data: that would move formatting out of the wrapper without
a consumer benefit and would make the data less reusable (a canvas renderer does not want
`s` glued to its durations). Bytes preserved either way.

## 4. Shipped `effects.js` is generated by folding the effect sources into one file

- **Gap.** Design decision 6 says the build emits "a framework-neutral bundle re-exporting
  the data functions", but a literal `export … from` barrel would couple `values/js/` to
  the layout of `zoo/source/` inside the release bundle, and the repo has no bundler
  dependency to inline it.
- **Done.** `build-core.mjs` concatenates the five effect sources in dependency order,
  stripping local imports and the zoo-build `implementsRecipes` metadata and de-exporting
  everything, then appends one explicit export list of the twelve data primaries. A load
  guard imports the emitted file during the build and fails if the public surface differs
  from the declared list. The `.d.ts` is authored beside the generator that emits the
  runtime so the two ship together.
- **Rejected.** Barrel re-export over `../../zoo/source/effects/*.mjs` (breaks if a consumer
  copies just `values/`; two surfaces for one module graph); adding esbuild/rollup as a
  dependency (unwarranted machinery for five dependency-free files); shipping the markup
  wrappers too (the spec's point is that consumers stop injecting markup strings).

## 5. Memo helper shared in `helpers.mjs`; defaults normalised before memoisation

- **Gap.** Task 2.2 says "add a module-level memo per data function" but not how eleven
  functions share the mechanism without copy-paste.
- **Done.** One `memoByArgs(fn)` in `effects/helpers.mjs`: a Map keyed by the argument
  (JSON-joined when arity > 1). Parametrised generators use a private memoised builder plus
  a thin defaulted export (`seedHeadData(n = 64) → headDots(n)`), so calling `seedHeadData()`
  and `seedHeadData(64)` hit the same cache slot. Repeat calls return the same array
  reference — design decision 4's observable stability — documented as read-only.

## 6. Contract test checks derivation both structurally and behaviourally

Task 5.6 ("wrapper renders from the data function") cannot be pinned by cardinality alone
(a wrapper could ignore its data and coincide). The test therefore asserts, per wrapper:
its own source names its data function (`String(wrapper)` contains the data fn — the
divider's chain is noted as transitive: `renderDivider → seedHead → seedHeadData`), and the
markup agrees with the data element-for-element in order (extracted `cx`/`--gi`/class/
custom-property sequences compared against the data arrays).

## 7. Architecture-test scope

Task 5.4 scans every `.mjs` under `design-system/source/zoo/effects/` — including
`deterministic-random.mjs` and `helpers.mjs`, which produce no field. Kept literal: the
clock-free rule is about the whole surface a generator may import, not only generators.

## Review rulings

Ruled during review against the repo constitution (modularity-first, no invented visual
values, byte-parity with the accepted baseline) and existing conventions — not against
whether each call is individually reasonable.

- **§1 spaces in weatherTextData — ACCEPT.** The only resolution that holds both spec
  halves for text runs without changing shipped bytes; the contract test pins it
  node-for-node, and ROADMAP-FEEDBACK.md asks future artifacts to settle the rule.
- **§2 `{cls,index,vars}` particle shape — ACCEPT.** One generic renderer for all eight
  fields, attribute order structural instead of lucky, no per-kind branching in wrappers;
  every field uses it today, so nothing here generalises for an imagined caller.
- **§3 unitless grid cells — ACCEPT.** Task 1.2 read literally; formatting stays in the
  wrapper where the bytes are made.
- **§4 fold-the-sources emission, no bundler dependency — ACCEPT.** Adds no dependency
  (the rejected esbuild/rollup option would have needed a project-document justification
  this change never made); keeps one module graph; load guard pins the export surface.
  The authored `.d.ts` is acceptable: the JS sources carry no types to derive from, and
  the distribution test compares shapes behaviourally against the same functions.
- **§5 shared `memoByArgs` — ACCEPT, simplified in review.** Sharing one mechanism was
  right; the `args.length <= 1 ? args[0] : JSON.stringify(args)` branch served no caller
  that exists (every call site passes zero or one argument). Keyed uniformly on
  `JSON.stringify(args)`, which also content-keys object arguments correctly.
- **§6 structural + behavioural derivation checks — ACCEPT.** The source-naming assertion
  alone would be brittle; paired with element-for-element agreement and the showcase's
  byte-parity oracle it is sound.
- **§7 clock-free scan over all effects modules — ACCEPT.** Strictly stronger than
  scanning generators only.

Review-phase edits (recorded here because they deviate from task text):

- Task 3.1 placed the effects emission "in `scripts/lib/build-core.mjs`"; review moved it
  verbatim to **`scripts/lib/effects-core.mjs`** (constants, source folder, `.d.ts`
  author, emitter/guard), imported by build-core. Same deviation C6 made when the skin
  engine moved to `skins-core.mjs`: build-core orchestrates, `*-core.mjs` engines compute.
- Strengthened contract task 5.2 ("every generator has a data primary"): the check now
  also asserts its hand-written module list equals the directory listing, so a future
  fourth effects module fails loudly instead of silently escaping the contract.
- The strengthened gate first went red: its whitelist named `deterministic-random.mjs`
  as the only non-field module but forgot `helpers.mjs`, which pre-dates this change
  (escapeHtml/cssVar, imported by the zoo sections) and which §5 above made
  load-bearing by moving `memoByArgs` into it. Fixed by naming it as a non-field
  helper — the mechanism the gate's own message prescribes — not by relocating
  `memoByArgs`: the memo is generic plumbing, not randomness, and helpers.mjs was
  already the shared module for exactly that kind of code.

## Final review pass — rulings confirmed, three further edits

Each ruling above was re-checked independently against the spec deltas, the
contract/distribution/showcase tests and the repo constitution: **all seven
accepted, none reverted**. Requirement-by-requirement, every scenario now has a
test that fails under violation. The pass also made three edits:

- **De-exported `EFFECTS_SOURCE_DIR`** (`scripts/lib/effects-core.mjs`): it was an
  exported constant with no importer anywhere in the repo — its single use is
  internal. The module's public surface is now exactly `emitEffectsModule`.
- **The weatherText contract check never saw a space.** It ran on the space-free
  'najaarswind', so the implementation §1 explicitly rejected (data drops spaces,
  wrapper re-inserts them) would have passed every contract test; only the
  page-wide byte oracle would have caught it, opaquely. The check now runs on the
  masthead's own 'de ontwerp' — the post-space glyph's asserted `--ci:3` pins
  spaces consuming an index — and `weatherTextData('de ontwerp')` joined the
  shared call list behind the structured-data, memo-identity and purity checks.
- **The shipped `.d.ts` was unguarded** (§4 accepts a hand-authored declaration):
  nothing failed if it stopped declaring an exported function. The distribution
  check now asserts every exported data function appears as `export function …`
  in `values/js/effects.d.ts`, so "matching type declaration" is enforced at the
  surface.
